# TX Power Calibration: Getting Flat Power Across Bands

Status: proposed procedure, not yet done! `data/hw_settings.ini`'s
`[tx_band]` scale table right now is still real sbitx's own bench
numbers, carried over unchanged - this document explains why those
numbers don't mean what they used to once they reach minibitx's TX
audio pipeline, and lays out a concrete bench procedure to re-derive
values that do.

## 1. Background

`hw_settings.ini` carries a `[tx_band]` section per HF band, each with
an `f_start`/`f_stop` range and a `scale` value. On real sbitx, this
table comes from `calibrate_band_power()` (`sbitx.c`) - an automated
routine that keys down on a dummy load, reads real forward power back
over I2C from a power/SWR bridge board, and walks `scale` up until the
band hits its target wattage. That's genuine, bench-verified,
per-band data, compensating for the PA's own gain rolloff across HF
(sbitx's own comment: *"the PA gain varies across the band from 3.5
MHz to 30 MHz here we adjust the drive levels to keep it up, almost
level"*).

minibitx has no power/SWR bridge on this board (`sBitx DE, original` -
confirmed absent at boot), so
that automatic feedback loop isn't available here at all - any
calibration has to be done by hand, watching an external wattmeter,
the same way the *board owner* originally calibrated real sbitx itself
(see the project history: "*My scale settings are calibrated on the
sbitx to produce 5 watts output with drive = 50*").

minibitx's CW TX audio, though, is generated by a completely different
pipeline than sbitx's: a plain oscillator + envelope
(`cw.c`/`sound.c`), not sbitx's FFT-domain modulator. Reusing sbitx's
*scale numbers* unchanged turned out to not work.

## 2. The problem: every band already hits the same ceiling

`sound.c` converts `hw_settings_tx_scale(freq)` into a PCM sample
amplitude, clamped to `TX_SAMPLE_CLAMP` (2×10⁹, safely under the
±2.147×10⁹ range a 32-bit PCM sample can hold at all). At the
`TX_GAIN_CORRECTION` value that got 40m to 6.1W, **every** band's
pre-clip amplitude already exceeds that clamp:

| Band | `scale` (sbitx's numbers) | Pre-clip amplitude | Clips? |
|---|---|---|---|
| 80m | 0.00075 | 2.6×10⁹ | yes |
| 60m | 0.00095 | 3.3×10⁹ | yes |
| 40m | 0.00115 | 4.0×10⁹ | yes (measured: 6.1W) |
| 30m | 0.00170 | 5.9×10⁹ | yes |
| 20m | 0.00332 | 1.16×10¹⁰ | yes |
| 17m | 0.00410 | 1.43×10¹⁰ | yes |
| 15m | 0.00520 | 1.81×10¹⁰ | yes |
| 12m | 0.00750 | 2.61×10¹⁰ | yes |
| 10m | 0.01070 | 3.72×10¹⁰ | yes |

Every row clips to the exact same 2×10⁹ ceiling. That means, as
things stand, **every band is driven to an identical saturated
waveform regardless of its `scale` entry** - the whole point of the
per-band table (give higher bands more drive to compensate for lower
PA gain) is currently defeated. Only the 40m/7.020MHz row has a real
wattmeter measurement behind it (6.1W); the other eight are unverified
guesses that happen to inherit the same saturated output level as
40m, for better or worse.

This has one important, non-obvious consequence for calibration:
**raising `scale` further can't add any more output once a band is
already clipping.** A larger pre-clip number just clips at the same
place. The only lever that still works, once you're above the
ceiling, is *lowering* `scale` back down toward - or below - wherever
the clamp starts to matter. So the calibration process below is a
process of finding out, band by band, how far below saturation to
back off - not a process of "add more drive."

## 3. What this means for hitting a flat 5W target

Two outcomes are possible per band, and they need different handling:

- **The band can reach 5W below the clamp.** Since 40m already
  measures *above* 5W (6.1W) while clipping, it's likely every band
  has at least that much headroom available before the clamp - in
  which case the fix is straightforward: back `scale` off until the
  wattmeter reads 5.0W, same as the board owner already did once for
  real sbitx.
- **The band can't reach 5W even fully saturated.** This would only
  happen if a band's real PA gain is low enough that even the maximum
  amplitude the pipeline can produce (the clamp ceiling) doesn't push
  5W out the antenna. If that shows up on a given band, no amount of
  `scale` tuning fixes it - the ceiling itself is the limit. Document
  the actual measured max for that band rather than chasing a target
  the pipeline can't reach; closing that gap would mean finding
  headroom somewhere else in the analog chain (see §5), not more
  `scale`.

Nothing here rules out the second case for the higher bands (15m/12m/
10m are exactly where sbitx's own table says the PA needs the *most*
help) - that's exactly what step 4 is for finding out.

## 4. Calibration procedure

No rebuild is needed between trials - `hw_settings.ini` is read once
at startup (`hw_settings_load()`, `hw_settings.c`), so each trial is
just: edit the file, restart minibitx, key down, read the meter.

For each of the 9 `[tx_band]` entries:

1. Pick one representative test frequency inside the band (the
   `f_start`/`f_stop` midpoint is fine, or reuse whatever frequency the
   antenna/dummy load is already set up for).
2. Tune there, hold the key down for a couple of seconds, and read the
   **steady** wattmeter value (not the initial turn-on kick - see the
   attack-transient note in `sound.c`'s comments).
3. If the steady reading is at or above 5W: reduce that band's `scale`
   value in `hw_settings.ini` (halve it as a first guess, then bisect
   up/down) and repeat step 2 until the steady reading is ~5.0W.
   Record the final `scale`.
4. If the steady reading is already below 5W with the existing
   (sbitx-derived) `scale`: that band is ceiling-limited, not
   `scale`-limited (see §3). Record the measured max power as-is;
   don't spend time raising `scale` further, since it's already
   clipping.
5. Move to the next band.

A record-keeping table for the results (the 40m row is already filled
in from the wattmeter session that found `TX_GAIN_CORRECTION`):

| Band | Test freq | sbitx `scale` | Measured power (sbitx `scale`, current pipeline) | Tuned `scale` for 5W | Notes |
|---|---|---|---|---|---|
| 80m | | 0.00075 | | | |
| 60m | | 0.00095 | | | |
| 40m | 7.020 MHz | 0.00115 | 6.1W (clipping) | | above target, back off `scale` |
| 30m | | 0.00170 | | | |
| 20m | | 0.00332 | | | |
| 17m | | 0.00410 | | | |
| 15m | | 0.00520 | | | |
| 12m | | 0.00750 | | | |
| 10m | | 0.01070 | | | |

Once every row has a tuned `scale`, replace the `scale=` lines in
`data/hw_settings.ini` with the new numbers - no code change needed,
since `hw_settings_tx_scale()` already looks these up per-band at TX
time.

## 5. If a band can't reach 5W

If step 4 turns up a genuinely ceiling-limited band, the options are,
roughly in order of effort:

- **Accept it and document the real number.** A slightly-under-5W CW
  signal on the hardest band is still a working signal; this may be
  perfectly fine for minibitx's scope as a support layer.
- **Check for a little spare clamp headroom.** `TX_SAMPLE_CLAMP` (2×10⁹)
  is set with some margin below the true ±2.147×10⁹ a 32-bit sample
  allows. Raising the clamp closer to that limit buys a small (~7%),
  fixed amount of extra headroom - worth trying, but it's a small
  knob, not a fix for a large shortfall.
- **Look for headroom outside the digital pipeline entirely** - e.g.
  whether `TX_DRIVE`/`TX_GAIN_CORRECTION`'s anchor could be
  restructured, or whether there's any other real analog gain stage
  available on this board. This is genuinely new investigation, not
  a tuning exercise, and shouldn't be assumed to exist without
  checking - PA gain rolloff across HF is a real hardware property,
  not something software can manufacture out of nothing.

Whatever the outcome, keep the measured-vs-target gap documented here
rather than silently accepted - a future board revision or PA change
is the kind of thing that would make it worth re-running this
procedure from scratch.
